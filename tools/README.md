# 솔루션 검증 도구

프로덕션에 올라간 솔버 결과물을 러스트 코드 없이 확인하는 파이썬 도구 두 개다.
`docs/blob-format.md` 스펙과 `src/blob.rs` 작성기를 그대로 옮겨 파서를 새로 짰기 때문에,
엔진이 자기 자신을 검증하는 구조가 아니라 독립된 두 번째 구현으로 대조하는 셈이 된다.

## 준비

```bash
PY=/Users/dong/projects/pokergoat/.venv/bin/python
$PY -m pip install brotli    # 유일한 외부 의존성
```

CDN 객체는 `Content-Encoding: br`로 서빙된다. 두 도구 모두 `Accept-Encoding: identity`로
저장된 바이트를 그대로 받아서 직접 푼다. 로컬 `.bin` 파일도 그대로 읽는다.

## read_blob.py

blob 하나를 열어 헤더, 노드, 전략, EV를 사람이 읽을 수 있게 찍는다.

```bash
$PY tools/read_blob.py <url-or-path> [옵션]
```

| 옵션 | 설명 |
|---|---|
| `--node N` | 노드 인덱스로 지정 |
| `--line 0.1.2` | 서브트리 루트에서 액션 인덱스를 따라 내려간 노드 |
| `--top N` | 가중치 상위 N개 핸드의 액션 분포 (기본 15) |
| `--range-oop FILE` / `--range-ip FILE` | 프리플랍 레인지 파일. 주면 실제 콤보 가중치로 집계한다 |
| `--normalized` | 상대 카드 제거를 반영한 가중치로 집계 (엔진의 normalized weights) |
| `--tree N` | 깊이 N까지 액션 빈도 트리 요약 |
| `--no-chain` | 턴/리버 파일에서 앞 스트리트 파일을 따라가지 않는다 |

출력은 헤더 요약(보드, 스트리트, 팟, 스택, 레이크, 익스플로이터빌리티, 반복 횟수),
지정 노드의 액션별 도달 가중 빈도와 액션 EV, 레인지 EV, 상위 핸드의 액션 분포다.

```bash
R=.../apps/solver/scenarios/ranges/c6m_100
$PY tools/read_blob.py \
  https://cdn.pokergoat.xyz/solutions/c6m_100_srp_btn_bb/v1/As9h4d/flop.bin.br \
  --line 0 --top 10 \
  --range-oop $R/bb_call_vs_btn.txt --range-ip $R/btn_open.txt
```

레인지 파일을 주지 않으면 모든 핸드의 가중치를 1로 본다. 레인지에 `22:0.5` 같은 부분
가중치가 있으면 빈도가 조금씩 달라지므로, 숫자를 인용할 일이면 파일을 같이 넘겨라.

### 턴/리버 파일 주의

턴 파일 하나에는 플랍 베팅 라인마다 서브트리가 하나씩 들어 있고, 각 서브트리 루트는
파일 안에 부모가 없다. 그래서 파일만 읽으면 그 라인이 이미 걸러 놓은 레인지를 알 수 없다.
도구는 URL 규칙(`turn/Kc.bin.br` -> `flop.bin.br`, `river/Kc/2d.bin.br` -> `turn/Kc.bin.br`)으로
앞 스트리트 파일을 자동으로 열어 찬스 노드까지의 도달 가중치를 이어받는다.
연결에 성공하면 그 사실을 한 줄로 알리고, 실패하면 경고를 찍은 뒤 프리플랍 레인지 기준으로
계산한다.

## verify_solutions.py

프로덕션 데이터에 포커 sanity 검사를 돌리고 PASS/FAIL 표를 찍는다.

```bash
$PY tools/verify_solutions.py [--per-scenario 6] [--cache DIR] [--scenarios-dir DIR]
```

- 시나리오 메타데이터는 `https://api.pokergoat.xyz/api/v1/solver/scenarios/`,
  플랍 목록은 `.../scenarios/{slug}/flops/`에서 받는다.
- 레인지는 API가 노출하지 않으므로 api 레포의 시나리오 JSON과 `ranges/*.txt`를 읽는다.
  기본 경로는 `--scenarios-dir`로 바꿀 수 있다.
- `--cache`를 주면 내려받은 blob을 디렉토리에 저장해 두 번째 실행부터 네트워크를 안 탄다.
- 표본은 텍스처가 겹치지 않게 결정적으로 뽑는다. 드라이 A하이 레인보우, 페어 A하이,
  로우 커넥티드, 모노톤을 우선 확보한 뒤 나머지를 균등 간격으로 채운다.

검사 항목은 다음과 같다.

| 키 | 검사 |
|---|---|
| S | 구조 무결성. 헤더 보드가 파일 경로와 같은지, 노드 id가 인덱스와 같은지, 노드 레코드와 전략·EV 섹션 길이 합이 파일 크기와 정확히 맞는지 |
| a | 전략 유효성. 핸드마다 액션 확률 합이 1인지, 저장 바이트 합이 255를 넘지 않는지(넘으면 마지막 액션이 음수), 음수와 NaN이 없는지 |
| b | 레인지 정합성. blob의 핸드 수가 프리플랍 레인지에서 보드로 막힌 콤보를 뺀 값과 일치하는지 |
| c | 익스플로이터빌리티가 시나리오 목표(0.3% pot) 이하인지, API가 보고한 값과 헤더 값이 같은지 |
| f | EV 보존. 양쪽 레인지 EV 합이 팟에서 레이크를 뺀 값인지. 레이크 없는 MTT는 오차 0.01bb 이내로 본다 |
| d1 | 드라이 A하이 레인보우에서 BB 체크 90% 초과, BTN 벳 45~90%, 작은 사이즈 우위 |
| d2a | 로우 커넥티드에서 BB 리드(돈크)가 A하이보다 훨씬 많은지 |
| d2b | 로우 커넥티드에서 BTN c벳이 더 낮은지 (조건부와 무조건부 둘 다 보고) |
| d3 | 페어 A하이에서 BB 체크가 매우 높고 IP의 큰 사이즈 사용이 0이 아닌지 |
| d4 | 블로커 sanity. 같은 메이드 클래스에서 A를 가진 핸드가 더 자주 컨티뉴하는지 |
| e | MTT 20bb 림프 팟의 팟 3.0, 스택 19.0, 트리 안에 올인 라인 존재 |

표 아래에 `c6m_100_srp_btn_bb`의 텍스처별 측정값 부록이 붙는다. 종료 코드는 FAIL이
하나라도 있으면 1이다.

## 한계

- 두 번째 독립 솔버가 없어서 전략 자체의 GTO 정합성은 대조하지 못한다. 검사하는 것은
  포맷 무결성, 수치 항등식(EV 보존), 그리고 방향성 수준의 포커 sanity다.
- 헤더의 익스플로이터빌리티는 엔진이 적은 값을 그대로 읽는다. 도구가 직접 베스트 리스폰스를
  다시 풀지는 않는다. 다만 노드 단위 베스트 리스폰스 갭은 `read_blob.py`의 액션 EV로
  손으로 확인할 수 있다.
- 표본은 플랍 파일 위주다. 턴과 리버 파일은 `read_blob.py`로 개별 확인할 수 있지만
  검증기는 자동으로 훑지 않는다.
